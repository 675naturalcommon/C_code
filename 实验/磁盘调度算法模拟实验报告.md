## 实验名称

## 实验目的
1. 深入理解磁盘调度算法的基本原理和工作机制

## 实验原理

### 1. 磁盘调度算法概述
磁盘调度算法是操作系统用于管理磁盘I/O请求的重要技术。当多个进程同时请求访问磁盘时，操作系统需要决定服务这些请求的顺序，以优化磁盘访问性能。主要优化目标包括：
- **最小化平均寻道时间**：减少磁头移动的总距离
- **最大化磁盘吞吐量**：单位时间内服务的请求数量
- **公平性**：避免某些请求长时间得不到服务（"饥饿"现象）
- **响应时间可预测性**：提供稳定的服务响应时间

### 2. 关键概念
- **磁道**：磁盘上的同心圆轨道，数据存储的位置
- **磁头**：读写数据的机械部件，可以在磁道间移动
- **寻道时间**：磁头从一个磁道移动到另一个磁道所需的时间
- **旋转延迟**：磁盘旋转到目标扇区所需的时间
- **传输时间**：实际读写数据所需的时间

### 3. 算法原理详解

#### 3.1 先来先服务算法 (FCFS - First Come First Served)
**基本原理**：
- 按照请求到达磁盘驱动器的先后顺序进行服务
- 维护一个简单的队列，新请求加入队尾，从队头取出请求服务

**数学表示**：
设请求序列为 R = {r₁, r₂, ..., rₙ}，当前磁头位置为 h
总移动距离：D = Σ|hᵢ - rᵢ|，其中 hᵢ 是服务第 i 个请求前的磁头位置
平均寻道长度：L = D / n

**特点**：
- 优点：实现简单，绝对公平，无"饥饿"现象
- 缺点：平均寻道时间较长，性能较差
- 适用场景：请求较少且分布均匀的情况

#### 3.2 最短寻道时间优先算法 (SSTF - Shortest Seek Time First)
**基本原理**：
- 总是选择距离当前磁头位置最近的请求进行服务
- 采用贪心策略，每次选择局部最优解

**算法步骤**：
1. 初始化：当前磁头位置 h，未服务请求集合 U
2. 循环直到所有请求被服务：
   a. 计算 U 中每个请求与 h 的距离：dᵢ = |h - rᵢ|
   b. 选择最小距离的请求 rⱼ：j = argmin(dᵢ)
   c. 服务请求 rⱼ，更新 h = rⱼ，从 U 中移除 rⱼ

**数学分析**：
- 时间复杂度：O(n²)，需要多次查找最近请求
- 空间复杂度：O(n)，需要存储访问状态

**特点**：
- 优点：平均寻道时间较短，性能较好
- 缺点：可能出现"饥饿"现象，远离磁头的请求可能长时间得不到服务
- 适用场景：请求密集且需要快速响应的系统

#### 3.3 扫描算法 (SCAN - Elevator Algorithm)
**基本原理**：
- 磁头从一端开始向另一端移动，服务沿途的所有请求
- 到达边界后反向移动，继续服务
- 类似电梯的运行方式，因此也称为"电梯算法"

**算法变种**：
1. **标准SCAN**：磁头移动到磁盘边界（0或MAX_TRACK-1）后反向
2. **LOOK算法**（SCAN改良版）：磁头移动到该方向上的最后一个请求后立即反向，无需到达边界

**数学表示**：
设磁头初始位置 h，移动方向 dir（+1表示增加，-1表示减少）
1. 对请求排序：R' = sort(R)
2. 根据方向选择服务顺序：
   - 如果 dir = +1：先服务所有 ≥ h 的请求，然后反向服务所有 < h 的请求
   - 如果 dir = -1：先服务所有 ≤ h 的请求，然后反向服务所有 > h 的请求

**特点**：
- 优点：避免了"饥饿"现象，服务比较均匀
- 缺点：两端的请求等待时间可能较长
- 适用场景：需要公平服务的系统

#### 3.4 循环扫描算法 (CSCAN - Circular SCAN)
**基本原理**：
- 磁头单向移动（通常从内向外），服务沿途的请求
- 到达边界后立即返回到另一端，继续单向移动
- 形成循环扫描的模式

**算法变种**：
1. **标准CSCAN**：磁头移动到磁盘边界后立即跳转到另一端
2. **CLOOK算法**（CSCAN改良版）：磁头移动到该方向上的最后一个请求后立即跳转到另一端的最小请求

**数学分析**：
- 总移动距离：包括单向扫描距离和跳转距离
- 平均等待时间：比SCAN更均匀，响应时间方差更小

**特点**：
- 优点：服务更加均匀，响应时间方差最小
- 缺点：跳转操作可能增加总移动距离
- 适用场景：需要稳定响应时间的实时系统

### 4. 性能指标
1. **总移动距离**：磁头移动的总磁道数
2. **平均寻道长度**：总移动距离除以请求数量
3. **最大等待时间**：单个请求的最长等待时间
4. **平均等待时间**：所有请求等待时间的平均值
5. **吞吐量**：单位时间内服务的请求数量

### 5. 算法比较
| 算法 | 平均寻道时间 | 公平性 | 实现复杂度 | 适用场景 |
|------|-------------|--------|------------|----------|
| FCFS | 最长 | 最好 | 最简单 | 教学演示、简单系统 |
| SSTF | 较短 | 较差 | 中等 | 性能要求高的系统 |
| SCAN | 中等 | 好 | 中等 | 需要公平服务的系统 |
| CSCAN | 中等 | 最好 | 较复杂 | 实时系统、稳定响应 |

### 2. 算法实现详情
本实验完整实现了四种磁盘调度算法及其改良版，共计11种算法：

#### 2.1 先来先服务算法 (FCFS)
**实现要点**：
- 严格按照输入顺序处理请求
- 无需排序或特殊处理
- 时间复杂度：O(n)，空间复杂度：O(1)

**代码特点**：
```c
// FCFS核心实现
for (int i = 0; i < req->n; i++) {
    moves[i] = abs(current - req->requests[i]);  // 计算移动距离
    sequence[i] = req->requests[i];              // 记录访问磁道
    current = req->requests[i];                  // 更新当前位置
}
```

#### 2.2 最短寻道时间优先算法 (SSTF)
**实现要点**：
- 使用贪心策略选择最近请求
- 需要维护访问状态数组
- 时间复杂度：O(n²)，空间复杂度：O(n)

**算法流程**：
1. 初始化所有请求为未访问状态
2. 循环直到所有请求被服务：
   a. 查找距离当前磁头最近的未访问请求
   b. 服务该请求并标记为已访问
   c. 更新磁头位置

#### 2.3 扫描算法 (SCAN) 及其改良版 (LOOK)
**SCAN实现要点**：
- 对请求进行排序
- 根据方向选择服务顺序
- 需要处理边界情况（0和MAX_TRACK-1）

**LOOK改进**：
- 不移动到物理边界，只移动到该方向上的最后一个请求
- 减少不必要的移动距离

**方向处理逻辑**：
```c
if (direction == 1) {  // 增加方向
    // 先服务所有 ≥ current 的请求
    // 然后反向服务所有 < head 的请求
} else {  // 减少方向
    // 先服务所有 ≤ current 的请求
    // 然后反向服务所有 > head 的请求
}
```

#### 2.4 循环扫描算法 (CSCAN) 及其改良版 (CLOOK)
**CSCAN实现要点**：
- 单向扫描，到达边界后跳转
- 形成循环访问模式
- 响应时间更加均匀

**CLOOK改进**：
- 跳转到另一端的最小请求，而不是物理边界
- 进一步优化移动距离

**跳转处理**：
```c
// CSCAN跳转到另一端
if (direction == 1) {
    moves[*count] = 0;
    sequence[*count] = 0;  // 跳转到最小磁道
    current = 0;
} else {
    moves[*count] = 0;
    sequence[*count] = MAX_TRACK - 1;  // 跳转到最大磁道
    current = MAX_TRACK - 1;
}
```

### 5. 访问链数据结构（算法输出结果）
```c

int sequence[MAX_REQUESTS];  // 访问序列数组：按算法顺序存储访问的磁道号
int moves[MAX_REQUESTS];     // 移动距离数组：存储每次访问的移动距离

// 使用示例（在算法函数内部）：
// FCFS算法的实现片段
void fcfs(const DiskRequest *req, int *sequence, int *moves, int *count, int direction) {
    int current = req->head;  // 从磁头当前位置开始
    *count = req->n;          // 访问次数等于请求数量

    for (int i = 0; i < req->n; i++) {
        moves[i] = abs(current - req->requests[i]);  // 计算移动距离
        sequence[i] = req->requests[i];              // 记录访问的磁道
        current = req->requests[i];                  // 更新当前位置
    }
}
```

### 7. 访问状态数组
```c
// 访问状态数组，用于SSTF算法标记已访问的请求
int visited[MAX_REQUESTS];  // 访问标记数组，0表示未访问，1表示已访问

// 使用示例（在sstf算法中）：
void sstf(const DiskRequest *req, int *sequence, int *moves, int *count, int direction) {
    // 1. 初始化访问状态数组
    for (int i = 0; i < req->n; i++) {
        visited[i] = 0;  // 所有请求初始状态为未访问
    }

    int current = req->head;  // 从磁头当前位置开始
    *count = 0;               // 初始化访问计数

    // 2. 循环选择最近的未访问请求
    while (*count < req->n) {
        int minDistance = MAX_TRACK * 2;  // 初始化最小距离为最大值
        int minIndex = -1;                // 初始化最近请求的索引

        // 3. 查找最近的未访问请求
        for (int i = 0; i < req->n; i++) {
            if (!visited[i]) {  // 只考虑未访问的请求
                int distance = abs(current - req->requests[i]);
                if (distance < minDistance) {
                    minDistance = distance;
                    minIndex = i;
                }
            }
        }

        // 4. 标记该请求为已访问，并记录结果
        visited[minIndex] = 1;            // 标记为已访问
        moves[*count] = minDistance;      // 记录移动距离
        sequence[*count] = req->requests[minIndex];  // 记录访问的磁道
        current = req->requests[minIndex];           // 更新当前位置
        (*count)++;                        // 增加访问计数
    }
}
```

### 8. 性能比较数据结构

// 性能比较数据结构，用于compareAlgorithms函数

float avgSeekLength;        // 平均寻道长度，总移动距离除以访问次数

// 使用示例（在compareAlgorithms函数中）：
void compareAlgorithms(const DiskRequest *req) {
    // 计算FCFS算法的性能
    int current = req->head;
    totalMove = 0;  // 初始化总移动距离

    for (int i = 0; i < req->n; i++) {
        totalMove += abs(current - req->requests[i]);  // 累加移动距离
        current = req->requests[i];                    // 更新当前位置
    }

    avgSeekLength = (float)totalMove / req->n;  // 计算平均寻道长度

    printf("FCFS算法 - 总移动距离: %d, 平均寻道长度: %.2f\n",
           totalMove, avgSeekLength);
}

## 实验结果分析

### 1. 算法性能比较
通过实验可以观察到：
- **FCFS算法**：实现简单，但平均寻道时间最长
- **SSTF算法**：平均寻道时间较短，但可能出现"饥饿"
- **SCAN/LOOK算法**：服务均匀，避免了"饥饿"
- **CSCAN/CLOOK算法**：响应时间方差最小

### 2. 适用场景
- **FCFS**：适用于请求较少且分布均匀的场景
- **SSTF**：适用于请求密集且需要快速响应的场景
- **SCAN/LOOK**：适用于需要公平服务的场景
- **CSCAN/CLOOK**：适用于需要稳定响应时间的场景
